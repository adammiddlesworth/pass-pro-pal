## Diagnostic auth flow

Goal: make the diagnostic feel built for brand-new visitors (Sign Up first) without breaking returning users who click a diagnostic link.

### Approach

1. **Public landing page** at `/diagnostic/$category` (move current route out of `_authenticated/`).
   - Shows the intro card ("Where do you stand?", ~20 questions, 10 min, weekly retake).
   - Primary CTA: "Create free account to start" → `/auth?mode=signup&next=/diagnostic/<category>`.
   - Secondary link: "Already have an account? Sign in" → same URL with `mode=signin`.
   - If the user is already authenticated, skip the CTA and show the "Start diagnostic" button that begins the quiz immediately (same behavior as today).

2. **Auth page tweaks** (`src/routes/auth.tsx`):
   - Read `mode` and `next` from search params.
   - Default the visible tab to Sign Up when `mode=signup`; Sign In when `mode=signin`.
   - When `next` starts with `/diagnostic/`, swap the page headline/subcopy to a diagnostic-flavored version ("Take a 10-minute diagnostic and see your readiness score.").
   - After successful signup or signin, redirect to `next` if present and same-origin; otherwise keep current default.

3. **Diagnostic route restructuring**:
   - Move the quiz/result flow into the same public route but gate the `startDiagnostic` call on an authenticated session — unauthenticated visitors only see the intro + CTA.
   - Update all internal links (`DiagnosticCard`, `select-track.tsx`, exams banner) to point to the new public path (unchanged URL, just no longer under `_authenticated/`).

4. **Server functions**: no changes — `startDiagnostic` / `completeDiagnostic` already `requireSupabaseAuth`, which is exactly the enforcement we want.

### Why not signup-only

A dedicated signup-only page would strand returning users who click a diagnostic link from an email, ad, or the dashboard. Defaulting the existing `/auth` page to the Sign Up tab gets the same "feels made for new users" effect while keeping Sign In one click away.

- Move `src/routes/_authenticated/diagnostic.$category.tsx` → `src/routes/diagnostic.$category.tsx`; add unauth intro variant with signup CTA.
- `src/routes/auth.tsx`: read `mode` + `next`, default tab, diagnostic headline, post-auth redirect.
- `src/components/DiagnosticCard.tsx`, `src/routes/_authenticated/select-track.tsx`, `src/routes/_authenticated/exams.index.tsx`: no URL change needed, but confirm links still resolve.
